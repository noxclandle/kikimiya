# 聴き宮（ききみや）

匿名の来訪者が「神父」と一対一で話せる、オンライン告解室。
同時に対応できるのは **1名のみ**。話し終えたあと、来訪者は任意の金額でお布施を送れます。

> **これはカウンセリングでも医療でもありません。** 人に言えないことを打ち明け、
> 神父がそれに応える場所です。神父は資格を持った専門家ではなく、返ってくるのは
> 診断や専門的助言ではなく、ひとりの人間の言葉です。
> この立場は入口ページの脚注と `/terms`（利用規約・免責事項）に明示しています。
> 緊急の相談窓口は、場の雰囲気を壊さないよう `/help` にまとめ、
> 全ページの footer と各ページの脚注からのみ辿れるようにしています。
> 公開前に、免責の文言と緊急相談窓口の連絡先を運営者ご自身で必ず確認・差し替えてください
> （窓口の一覧は [`lib/helplines.ts`](lib/helplines.ts)）。

## 構成

**ひとつのプロセスで動きます。** 常時起動のサーバーは要りません。

```
ブラウザ ──HTTP──▶ Next.js（画面 + /api/*）        … Vercel など
   │                    │
   │                    └──▶ Supabase（手紙の保存・在室や順番の記録）
   └──WebSocket──▶ Supabase Realtime（在室・順番・入室案内・告解室）
```

判断（同時1名・順番・在室）はすべて `/api/*` の中で下し、
その結果だけを Supabase Realtime の「通り道」に流してブラウザへ届けます。
**声と告解室の文字は、どのサーバーも通りません**（ピア間を直接ゆき来します）。

| | 役割 |
|---|---|
| `app/` | 画面（App Router）と `/api/*`（在室・入退室・手紙・神父の操作・Stripe） |
| `lib/server/` | Supabase への読み書き、席と順番の管理、神父の簡易認証、連投の抑制 |
| `lib/` | 画面側の部品と、通り道・生存信号・WebRTC のロジック |
| `supabase/schema.sql` | テーブル定義。Supabase の SQL Editor に貼って実行する |

### 画面

| パス | 内容 |
|---|---|
| `/` | 入口。在室状況と席の埋まり具合（`0/1` `1/1`）をリアルタイム表示。並ぶ・呼ばれたら入る、不在なら文章送付へ誘導 |
| `/room/[sessionId]` | 告解室。音声（WebRTC）＋文字、音量スライダー、ミュート、経過時間、接続状態、お布施、「つらい」ボタン、退室 |
| `/message` | 文章を預ける。送信後、返信を読むための一意なURLを発行（ログイン不要） |
| `/message/[token]` | 預けた文章と、神父からの返信を読む |
| `/admin`（隠せます） | 神父専用の待機所（合言葉で保護）。在室切替、**待機列から一人ずつ入室させる**、追放、来訪の知らせ、手紙の既読管理と返信、当日の統計、設定 |
| `/terms` | 利用規約・免責事項 |
| `/help` | 相談窓口の一覧（各ページの footer から辿れます） |
| `/thanks` | お布施の完了 |

## はじめかた

```bash
npm install
cp .env.example .env
npm run dev
```

`.env` には最低限この4つが要ります。

| 変数 | 取り方 |
|---|---|
| `ADMIN_PASSWORD` | 自分で決める。`/admin` の合言葉 |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase の Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 同上（公開してよい鍵） |
| `SUPABASE_SECRET_KEY` | 同上（**絶対に公開しない鍵**） |

はじめに一度だけ、[`supabase/schema.sql`](supabase/schema.sql) を
Supabase の SQL Editor に貼り付けて実行してください。何度実行しても壊れません。

- 画面: http://localhost:3000

### 動かしてみる

1. ブラウザAで `/admin` を開き、`ADMIN_PASSWORD` の合言葉でログイン → **オンラインにする**
2. ブラウザB（別ウィンドウか別プロファイル）で `/` を開くと「在室」になっている → **順番に並ぶ**
3. `/admin` の待機列に現れ、鐘が鳴る → **入室させる** を押す
4. ブラウザBに「お部屋が空きました」→ **入室する**
5. `/admin` の **告解室へ入る** で神父も同じ部屋に入る
6. 双方で **マイクを許可して声でつなぐ** を押すと音声がつながります（文字だけでも会話できます）

## 主要な環境変数

秘密の値はコードに書かず、すべて環境変数から読み込みます。詳細は [`.env.example`](.env.example) を参照。

| 変数 | 置き場所 | 説明 |
|---|---|---|
| `ADMIN_PASSWORD` | サーバー | `/admin` の合言葉。**必須**。5回間違えると15分締め出します |
| `NEXT_PUBLIC_SUPABASE_URL` | 両方 | Supabase のプロジェクトURL。**必須** |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | フロント | 公開してよい鍵。リアルタイムの購読だけに使います。**必須** |
| `SUPABASE_SECRET_KEY` | サーバー | RLS を迂回できる鍵。漏れると預かった手紙が全部読まれます。**必須** |
| `ADMIN_PATH` | サーバー | 待機所の隠し入口。設定すると `/admin` は 404 になります（任意） |
| `STRIPE_SECRET_KEY` | サーバー | Stripe のシークレットキー。まず `sk_test_…` で確認 |
| `STRIPE_DONATION_PRICE_ID` | サーバー | 自由金額の Price。未設定なら初回に自動作成します |
| `STRIPE_WEBHOOK_SECRET` | サーバー | お布施が入ったことを受け取るための `whsec_…` |
| `NEXT_PUBLIC_STRIPE_PAYMENT_LINK` | フロント | Payment Link 方式を使う場合のみ |
| `DISCORD_PURCHASE_WEBHOOK_URL` | サーバー | お布施が入ったときの通知先 |
| `NEXT_PUBLIC_TURN_URLS` | フロント | 音声の中継（TURN）。携帯回線の相手と繋がるかを左右します |

`NEXT_PUBLIC_` の値は**ビルド時に埋め込まれます**。変えたらビルドし直してください。

## 仕組みのメモ

### ハートビート（在室確認）

繋ぎっぱなしの線を持たないので、居るあいだだけ短い便りを送り続けます。

| 誰が | 送る間隔 | 途切れたときの扱い |
|---|---|---|
| 神父（待機所・告解室を開いているあいだ） | 30秒 | **120秒**で「不在」 |
| 並んで待っている人 | 10秒 | **5分**で列から外れる |
| 告解室に居る人 | 10秒 | **90秒**で退室（席を早く空けるため、ここだけ短い） |

許容時間を長めに取っているのには理由があります。**ブラウザは裏に回ったタブの
タイマーを間引きます**（多くの環境で1分に1回程度）。待機所を開いたまま別の作業をする神父も、
順番待ちのあいだスマホの画面を消す来訪者も、送っているのに届かない状態になります。
短く切ると、居るのに追い出してしまいます。

入口を眺めているだけの人は何も送りません（席にも列にも載っていないため）。

掃除は、誰かが訪ねてきた「ついで」に行います。常駐するサーバーが無いので、
誰も来ていないあいだは掃除も要らない、という考え方です。
**片づけるものが無ければ、書き込みは一度も起きません。**

### 順番待ちと、神父が通す仕組み

**自動では誰も入室しません。**部屋が空いていても、来訪者はいったん列に並びます。
誰をいつ通すかは、`/admin` で神父が決めます。

```
来訪者：「順番に並ぶ」 → 列に並ぶ（席は空いたまま 0/1）
神父　：待機所で鐘が鳴る → 「入室させる」を押す
来訪者：「お部屋が空きました」→「入室する」→ 告解室へ
```

心の準備が要る話を聴く場所なので、開いた瞬間に見知らぬ人が座っているのではなく、
**神父が支度を整えてから一人ずつ迎えられる**ようにしています。
順番を飛ばして誰を先に呼ぶかも神父が選べます。

- 案内してから決めた秒数（`/admin` の設定。既定60秒）返事が無ければ、**その人は列から外れます**。
  列に戻すと先頭に居座り続け、何度呼んでも同じ人に当たってしまうためです。
  外れたことは本人の画面に伝わるので、戻ってきたら並び直せます
- 対応中・案内中は、ほかの人を呼べません（押しても断られます）
- 神父がオフラインにすると、対応中のセッションは終了し、待機列は解散します

「席がひとつ」であることは、入口にも `0/1` `1/1` と数で出しています。
データベース側にも部分一意索引を張ってあり、**同時に二人が座ることはできません**
（関数は並列に起動するので、確認してから座るだけでは防げないため）。

### 音声（WebRTC）と、告解室の文字

一対一の音声通話です。繋ぐための打ち合わせ（シグナリング）だけを
Supabase Realtime の通り道に通し、**声そのものはピア間を直接ゆき来します**。
神父側が発信側です。

告解室の文字も同じ通り道を直接ゆき来します。**サーバーにもデータベースにも残しません。**
再読み込みで話の流れを見失わないよう、自分のブラウザのタブ内にだけ控えを置き、
退室すると同時に消します。

マイク音量は Web Audio の GainNode を通してから送るため、スライダーを下げると
**相手に届く声そのもの**が小さくなります。ミュートはトラックを直接無効化するので即座に効きます。

「音声途切れ検知」は `RTCPeerConnection.getStats()` の受信バイト数を2秒ごとに見て判定しています。

#### 中継（TURN）

STUN だけでは、**携帯回線や職場・学校のネットワークから来た相手とは音声が繋がらないことがあります**
（対称NAT）。相手を待たせている最中に分かるので、ずっと運用するなら中継を用意してください。

`NEXT_PUBLIC_TURN_URLS` にカンマ区切りで並べます（提供元は udp / tcp / 443番 の複数URLを配ることが多く、
どれかが塞がれていても別の経路で通ります）。`NEXT_PUBLIC_TURN_USERNAME` と
`NEXT_PUBLIC_TURN_CREDENTIAL` も併せて設定します。

繋がる見込みは **`/admin` の「声の通り道 → 確かめる」** でいつでも試せます。
`中継 ○` と出れば、相手の回線を選ばず繋がります。

### 背景の絵

2枚の絵を、場面に対応させて全面の背景に敷いています。

| 場面 | 画面 |
|---|---|
| 夕暮れの聖堂（外） | `/`、`/message`、`/message/[token]`、`/thanks`、対話の終了画面 |
| 格子ごしの告解室（中） | `/room/[sessionId]` |

入口の聖堂は、**神父が不在のあいだ灯りが落ちます**（`Backdrop` の `dimmed`）。
`/message` は不在時に開かれる画面なので、はじめから灯りを落としています。

- 元の画像は `ass/`、配信用に軽くしたものが `public/images/`
- 差し替えるときは `public/images/` の2枚を置き換えてください。暗幕の濃さや
  切り取り位置は [`components/Backdrop.tsx`](components/Backdrop.tsx) の
  `SCENES` と `VEIL` で調整できます
- 写真は `img` ではなく CSS の `background-image` で敷いています。
  全画面固定レイヤーの中の `img` は、環境によって初回描画で塗られないことがあるためです

### 呼ばれたことに気づく仕掛け（来訪者側）

神父が一人ずつ通す形なので、来訪者は「呼ばれる瞬間」を待つことになります。
画面を見つめ続ける人はいないので、待機所と同じ仕掛けを来訪者側にも置いています。

- **鐘の音** — 呼ばれると鳴り続けます（「順番に並ぶ」を押した操作があるので、ブラウザは音を出せます）
- **タブの見出し** — 待機中は「お待ちいただいています（2番目）」、呼ばれると「● お呼びです」
- **待ち時間** — 5分を超えると「文章で預けておく」ほうを勧める案内が出ます

### 離席中の知らせ方（`/admin`）

神父は待機所を開いたまま離れている前提なので、来訪に気づくための仕掛けを入れています。

- **鐘の音** — 来訪がある間、確認するまで鳴り続けます。`setInterval` ではなく
  `<audio loop>` で鳴らしているので、タブが裏にあっても間引かれません。
  ブラウザの自動再生制限があるため、画面を一度でも操作すると鳴らせるようになります
  （「鳴らしてみる」で明示的に許可もできます）
- **デスクトップ通知** — 別のアプリを見ていても画面に出ます。`requireInteraction` 付き
- **タブのタイトルとファビコン** — 裏のタブでも「● 来訪者があります」と分かります
- **画面を消さない** — Wake Lock。任意で有効にできます
- **接続が切れたときの警告** — 在室のつもりなのに回線が切れると、別の音と赤い警告で知らせます。
  在室の意思は保存してあるので、**回線やサーバーが復帰すると自動的に在室へ戻します**
- **待たせたままなら自動で離席** — お待ちの方がいるのに一定時間（既定10分）まったく操作が無ければ、
  自動で離席にし、待っている人には「席を外した」旨を伝えます。
  席を外したまま延々と待たせるより正直だからです。時間は待機所で変えられます（しないことも選べます）
- **合言葉の入れ直しが要らない** — トークンは12時間で切れますが、期限が近づくと
  在室の信号のついでに差し替えます。何日開けたままでも落ちません

### 保存するもの・しないもの

| | 保存 |
|---|---|
| 音声 | **しない**（ピア間で直接やりとりし、サーバーを通りません） |
| 告解室の文字 | **しない**。相手の画面へ直接届き、控えは自分のタブの中だけ。退室と同時に消えます |
| 手紙（`/message`） | **する**（Supabase）。返事をお返しするために必要なため。これだけが例外です |
| 統計 | 件数と対話時間の合計のみ。個人を特定する情報は含みません |
| IPアドレス | 記録しません。連投を抑えるとき（手紙・ログイン試行）は、秘密鍵で**HMACした値**だけを数えます。元のIPには戻せません |

手紙の保存先は Supabase です。ブラウザからテーブルには一切触れません
（RLS を有効にしてポリシーを1つも作らず、公開鍵からは何も読めないようにしてあります）。
読み書きはすべて、秘密鍵を持つ `/api/*` を通ります。

### 待機所の入口を隠す

待機所は身内しか使わないので、**入口の名前ごと隠せます**。
`ADMIN_PATH` に当てられない名前を入れると、その名前でだけ開き、`/admin` は 404 になります。

```
ADMIN_PATH=k7m2q9x4v8n3b6t1w5r0
  → https://example.com/k7m2q9x4v8n3b6t1w5r0  で待機所が開く
  → https://example.com/admin                  は「無い」と答える
```

- 隠し名で開いても、**URLはその名前のまま**表示されます（[middleware.ts](middleware.ts) で中身を差し替えているだけ）
- 検索の網にかからないよう `X-Robots-Tag: noindex` を付けています
- 告解室から待機所へ戻る導線は、開いたときの名前を覚えて使います
- 未設定なら、これまでどおり `/admin` が開きます（設定漏れで締め出されないように）

> **これは鍵ではなく目隠しです。** 当てずっぽうで辿り着かれることは防げますが、
> URLが一度でも人目に触れれば意味を失います。肩越しに見られる、履歴が残る、
> 誰かに転送する、それだけで漏れます。**合言葉（`ADMIN_PASSWORD`）は必ず併用してください。**
> 入れるかどうかを決めているのは、いまも合言葉のほうです。

### 認証

`/admin` は `ADMIN_PASSWORD` との照合のみ（会員登録なし）。
関数は毎回まっさらな状態で起動するので発行済みトークンを覚えておけません。
代わりに **「有効期限＋署名」を含んだトークン**を発行し、署名の検証だけで済ませています
（有効12時間。合言葉を変えると、発行済みのトークンはすべて無効になります）。

待機所へ流すリアルタイムの通り道の名前も、合言葉から導いた署名で作っています。
合言葉を知らなければ算出できないので、他人には覗けません。

## デプロイ

**Vercel だけで動きます。**常時起動のサーバーは要りません。

1. Supabase でプロジェクトを作り、[`supabase/schema.sql`](supabase/schema.sql) を SQL Editor で実行する
2. Vercel に接続し、環境変数（上の表の**必須**4つ）を入れる
3. デプロイする

### Stripe

**既にお使いの Stripe アカウントをそのまま使えます。** 詳しい手順は [DEPLOY.md](DEPLOY.md) の4章へ。
一番簡単なのは、自由金額の Payment Link を作って
`NEXT_PUBLIC_STRIPE_PAYMENT_LINK` に貼る方法で、シークレットキーは要りません。

1. まずテストモード（`sk_test_…`）で確認します
2. `STRIPE_SECRET_KEY` だけを設定すると、初回のお布施のときに「金額はお客様が決める」Price を
   自動作成し、そのIDをログに出します。以降は `STRIPE_DONATION_PRICE_ID` に設定しておくと確実です
3. お布施が入ったことを知るには、`/api/stripe/webhook` を Stripe に登録し
   （受け取るイベントは `checkout.session.completed` だけでよい）、
   得られた `whsec_…` を `STRIPE_WEBHOOK_SECRET` に入れます
4. どちらも未設定なら、お布施ボタンは「準備中」の案内を返します
