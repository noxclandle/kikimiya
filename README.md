# 聴き宮（ききみや）

匿名の来訪者が「神父」と一対一で話せる、オンライン告解室。
同時に対応できるのは **1名のみ**。話し終えたあと、来訪者は任意の金額でお布施を送れます。

> **これはカウンセリングでも医療でもありません。** ただ話を聴くだけのサービスです。
> この立場は入口ページの脚注と `/terms`（利用規約・免責事項）に明示しています。
> 緊急の相談窓口は、場の雰囲気を壊さないよう `/help` にまとめ、
> 全ページの footer と各ページの脚注からのみ辿れるようにしています。
> 公開前に、免責の文言と緊急相談窓口の連絡先を運営者ご自身で必ず確認・差し替えてください
> （窓口の一覧は [`lib/helplines.ts`](lib/helplines.ts)）。

## 構成

2つのプロセスで動きます。フロントは Vercel、リアルタイム側は Render など
**常時起動できる環境**に置く想定です。

```
ブラウザ ──HTTP──▶ Next.js（フロント + Stripe決済API）      … Vercel など
   │
   └──WebSocket──▶ Node サーバー（Socket.io + 文章メッセージAPI） … Render など（常時起動）
```

| | 役割 |
|---|---|
| `app/` | 画面（App Router）と `/api/donate`（Stripe Checkout Session の作成） |
| `server/` | Socket.io、在室確認、キュー管理、文章メッセージの保存、簡易認証 |
| `components/`, `lib/` | 画面部品と、socket・ハートビート・WebRTC などのクライアント側ロジック |

### 画面

| パス | 内容 |
|---|---|
| `/` | 入口。神父の在室状況（不在／在室／対応中）をリアルタイム表示。満室なら順番待ち、不在なら文章送付へ誘導 |
| `/room/[sessionId]` | 告解室。音声（WebRTC）＋文字、音量スライダー、ミュート、経過時間、接続状態、お布施、「つらい」ボタン、退室 |
| `/message` | 文章を預ける。送信後、返信を読むための一意なURLを発行（ログイン不要） |
| `/message/[token]` | 預けた文章と、神父からの返信を読む |
| `/admin` | 神父専用の待機所（合言葉で保護）。在室切替、来訪者・待機列、追放、通知、文章の既読管理と返信、当日の統計、設定 |
| `/terms` | 利用規約・免責事項 |
| `/help` | 相談窓口の一覧（各ページの footer から辿れます） |
| `/thanks` | お布施の完了 |

## はじめかた

```bash
npm install
cp .env.example .env   # ADMIN_PASSWORD だけは必ず設定してください
npm run dev
```

- フロント: http://localhost:3000
- リアルタイム側: http://localhost:3001

`npm run dev` は Next.js と Socket.io サーバーを同時に起動します。
片方だけ動かす場合は `npm run dev:web` / `npm run dev:socket` を使います。

### 動かしてみる

1. ブラウザAで `/admin` を開き、`ADMIN_PASSWORD` の合言葉でログイン → **オンラインにする**
2. ブラウザB（別ウィンドウか別プロファイル）で `/` を開くと「在室」になっている → **入室する**
3. `/admin` に来訪者が現れる → **告解室へ入る** で神父も同じ部屋に入る
4. 双方で **マイクを許可して声でつなぐ** を押すと音声がつながります（文字だけでも会話できます）

## 主要な環境変数

秘密の値はコードに書かず、すべて環境変数から読み込みます。詳細は [`.env.example`](.env.example) を参照。

| 変数 | 置き場所 | 説明 |
|---|---|---|
| `ADMIN_PASSWORD` | サーバー | `/admin` の合言葉。**必須**。5回間違えると15分締め出します（`LOGIN_FAIL_LIMIT` / `LOGIN_LOCK_MS`） |
| `NEXT_PUBLIC_SERVER_URL` | フロント | Socket.io サーバーのURL |
| `ALLOWED_ORIGINS` | サーバー | 接続を許可するオリジン（カンマ区切り） |
| `STRIPE_SECRET_KEY` | フロント側のAPI | Stripe のシークレットキー。まず `sk_test_…` で確認 |
| `STRIPE_DONATION_PRICE_ID` | 同上 | 自由金額の Price。未設定なら初回に自動作成します |
| `NEXT_PUBLIC_STRIPE_PAYMENT_LINK` | フロント | Payment Link 方式を使う場合のみ |
| `DATA_DIR` | サーバー | 文章メッセージの保存先（既定 `./data`） |
| `HEARTBEAT_TIMEOUT_MS` | サーバー | この時間 信号が届かない接続を自動退室にする（既定 15000） |
| `REPLY_ETA_DAYS` | サーバー | 「返信の目安：◯日以内」の初期値（`/admin` から変更可） |
| `INVITE_TIMEOUT_SECONDS` | サーバー | 順番が来た人を待つ秒数（`/admin` から変更可） |

## 仕組みのメモ

### ハートビート（在室確認）

クライアントは5秒ごとに `heartbeat` を送ります。サーバーは3秒ごとに全接続を点検し、
15秒（`HEARTBEAT_TIMEOUT_MS`）信号が届かない来訪者を**自動的に退室扱い**にして、
入口ページと待機ページの表示を更新します。

切断してすぐ消すのではなく猶予を置いているため、**ページ遷移や短い回線断は吸収され、
ブラウザを閉じた場合はタイムアウトで確実に退室になります**。
8秒（`HEARTBEAT_STALE_MS`）を超えると、神父の画面と告解室に「応答なし」が表示されます。

### 同時接続制御とキュー

対応中は1名のみ。2人目以降は待機列に入ります。対応中の人が退室・切断すると、
待機列の先頭に入室案内が飛び、`INVITE_TIMEOUT_SECONDS` 以内に応答がなければ次の人に回ります。
神父がオフラインにすると、対応中のセッションは終了し、待機列は解散します。

### 音声（WebRTC）

Socket.io をシグナリングに使う一対一の音声通話です。神父側が発信側になります。
マイク音量は Web Audio の GainNode を通してから送るため、スライダーを下げると
**相手に届く声そのもの**が小さくなります。ミュートはトラックを直接無効化するので即座に効きます。

「音声途切れ検知」は `RTCPeerConnection.getStats()` の受信バイト数を2秒ごとに見て判定しています。

STUN だけで通らない回線（対称NATなど）向けに、`NEXT_PUBLIC_TURN_URL` で TURN を設定できます。

### 背景の絵

2枚の絵を、場面に対応させて全面の背景に敷いています。

| 場面 | 画面 |
|---|---|
| 夕暮れの聖堂（外） | `/`、`/message`、`/message/[token]`、`/thanks`、対話の終了画面 |
| 格子ごしの告解室（中） | `/room/[sessionId]` |

入口の聖堂は、**神父が不在のあいだ灯りが落ちます**（`Backdrop` の `dimmed`）。
`/message` は不在時に開かれる画面なので、はじめから灯りを落としています。

- 元の画像は `ass/`、配信用に軽くしたものが `public/images/`
- 差し替えるときは `public/images/` の2枚を置き換えてください。暗幕の濃さや
  切り取り位置は [`components/Backdrop.tsx`](components/Backdrop.tsx) の
  `SCENES` と `VEIL` で調整できます
- 写真は `img` ではなく CSS の `background-image` で敷いています。
  全画面固定レイヤーの中の `img` は、環境によって初回描画で塗られないことがあるためです

### 離席中の知らせ方（`/admin`）

神父は待機所を開いたまま離れている前提なので、来訪に気づくための仕掛けを入れています。

- **鐘の音** — 来訪がある間、確認するまで鳴り続けます。`setInterval` ではなく
  `<audio loop>` で鳴らしているので、タブが裏にあっても間引かれません。
  ブラウザの自動再生制限があるため、画面を一度でも操作すると鳴らせるようになります
  （「鳴らしてみる」で明示的に許可もできます）
- **デスクトップ通知** — 別のアプリを見ていても画面に出ます。`requireInteraction` 付き
- **タブのタイトルとファビコン** — 裏のタブでも「● 来訪者があります」と分かります
- **画面を消さない** — Wake Lock。任意で有効にできます
- **接続が切れたときの警告** — 在室のつもりなのに回線が切れると、別の音と赤い警告で知らせます。
  在室の意思は保存してあるので、**回線やサーバーが復帰すると自動的に在室へ戻します**

### 保存するもの・しないもの

| | 保存 |
|---|---|
| 音声 | **しない**（ピア間で直接やりとりし、サーバーを通りません） |
| 告解室の文字 | **しない**。対話中だけメモリ上に置き（再読み込みで戻れるように）、終了と同時に破棄 |
| 手紙（`/message`） | **する**。返事をお返しするために必要なため。これだけが例外です |
| 手紙に添えられた名前・メール・性別・年代 | **する**（すべて任意入力。空欄でも送れます）。手紙を削除すると一緒に消えます |
| 統計 | 件数と対話時間の合計のみ。個人を特定する情報は含みません |
| IPアドレス | 記録しません。連投を抑えるレート制限では、起動ごとに変わるソルトで**ハッシュ化した値**だけをメモリ上に持ちます |

文章メッセージの保存先は `DATA_DIR` のJSONファイルです。ディスクを持つホスト（Render 等）を
前提にしています。Vercel など書き込みできない環境にリアルタイム側を置く場合は、
[`server/store.ts`](server/store.ts) の保存部分をDBに差し替えてください。

### 認証

`/admin` は `ADMIN_PASSWORD` との照合のみ（会員登録なし）。成功するとメモリ上に
12時間有効なトークンを発行します。**サーバーを再起動するとトークンは失効し、再ログインが必要です。**

## デプロイ

手順は [DEPLOY.md](DEPLOY.md) にまとめてあります（サブドメインの設定、Vercel で足りない理由、
Stripe の手順、`ALLOWED_ORIGINS` の意味）。Render 用の設定は [render.yaml](render.yaml)。


### フロント（Vercel など）

環境変数に `NEXT_PUBLIC_SERVER_URL`、`NEXT_PUBLIC_BASE_URL`、`STRIPE_SECRET_KEY` を設定して、
通常どおり `npm run build` / `npm start`。

### リアルタイム側（Render など、常時起動）

WebSocket を維持できる環境が必要です（サーバーレスでは動きません）。

- 起動コマンド: `npm run start:socket`
- 環境変数: `ADMIN_PASSWORD`、`ALLOWED_ORIGINS`（フロントの本番URL）、`DATA_DIR`（永続ディスク）
- `DATA_DIR` には永続ディスクを割り当ててください。割り当てないと、預かった文章が再起動で消えます

### Stripe

**既にお使いの Stripe アカウントをそのまま使えます。** 詳しい手順は [DEPLOY.md](DEPLOY.md) の4章へ。
一番簡単なのは、自由金額の Payment Link を作って
`NEXT_PUBLIC_STRIPE_PAYMENT_LINK` に貼る方法で、シークレットキーは要りません。

1. まずテストモード（`sk_test_…`）で確認します
2. `STRIPE_SECRET_KEY` だけを設定すると、初回のお布施のときに「金額はお客様が決める」Price を
   自動作成し、そのIDをログに出します。以降は `STRIPE_DONATION_PRICE_ID` に設定しておくと確実です
3. ダッシュボードで自由金額の Payment Link を作り、`NEXT_PUBLIC_STRIPE_PAYMENT_LINK` に
   入れるだけでも動きます（この場合サーバー側のキーは不要）
4. どちらも未設定なら、お布施ボタンは「準備中」の案内を返します
